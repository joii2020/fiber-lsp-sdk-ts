# Local devnet

Like fiber-lab, this setup uses offckb to manage CKB and three Fiber nodes, with Node3 as the LSP. Run initialization, startup, shutdown, cleanup, and reset scripts directly with `sh`.

Initialization uses offckb, Node.js 24, the project's `js-yaml` dependency, and biscuit-cli 0.6. `configure.ts` updates only Node3's YAML configuration. `biscuit` issues the operator token using the private key generated by offckb.

Before initialization, build `fnn` from the same Fiber commit as the SDK's WASM dependency, `5da02c0d0843b5a690eb82a8cc915bf7b4438693`. Run this command in that Fiber checkout.

```sh
cargo build --locked --release -p fiber-bin --bin fnn --features lsp
```

`FNN_PATH` defaults to `../fiber/target/release/fnn` relative to the SDK repository root. If your executable is elsewhere, set `FNN_PATH` to its absolute path. [config.sh](config.sh)

Keep the old node data, browser signer storage, and SDK together if you need to manage pre-V2 channels. Use a separate devnet and fresh signer storage for V2 channels.

```sh
# First run: initialize, and start the environment.
sh examples/devnet/init.sh

# Stop while keeping data, then start again.
sh examples/devnet/stop.sh
sh examples/devnet/start.sh
```

```sh
sh examples/devnet/clean.sh  # Stop nodes; remove offckb data and this project's .devnet/.
sh examples/devnet/reset.sh  # Clean, initialize with the configured fnn, and start.
```

`init.sh` stops existing Fiber and CKB processes, starts CKB, initializes three Fiber nodes, configures Node3 LSP and the project's operator token, then starts Fiber. Stopping keeps chain data and node keys, so initialization can be rerun on an existing environment.

`start.sh` starts CKB and Fiber with the existing configuration, keys, and chain data. As in fiber-lab, offckb reports an error if they are already running. Stop before restarting.

`clean.sh` deletes chain and node data, along with user data and operator tokens in `.devnet/`. `reset.sh` runs `clean.sh` followed by `init.sh`.

offckb stores node data in `${XDG_DATA_HOME:-$HOME/.local/share}/offckb-nodejs/devnet`. The project's operator token is stored in `.devnet/keys/operator-token`. Default ports are CKB `8114`, LSP HTTP `21716`, and WebSocket `21717`.

With a custom XDG directory, use the same environment variables for initialization, startup, shutdown, and the example server.
